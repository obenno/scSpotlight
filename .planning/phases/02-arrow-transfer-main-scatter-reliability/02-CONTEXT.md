# Phase 2: Arrow Transfer & Main Scatter Reliability - Context

**Gathered:** 2026-06-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 2 makes the existing Arrow IPC transfer and main deck.gl scatter paths dependable at large scale. The scope covers metadata, reductions, expression vectors, PCA summaries, column-scoped metadata patches, visible transfer/render failures, versioned cache behavior, adaptive main scatter rendering, grouping/splitting geometry, legends/labels/titles, and lasso synchronization across panels.

This phase does not add new analysis workflows, new portable artifact formats, new floating panel behavior, or assistant functionality. It hardens the runtime path that lets already-loaded data reach the browser and remain interactively inspectable.

</domain>

<decisions>
## Implementation Decisions

### Transfer Failure Visibility
- **D-01:** Treat fetch, decode, and IPC write failures as visible plot-state failures, not silent console-only errors or stuck waiters.
- **D-02:** Prefer in-plot or plot-adjacent error state that leaves enough context for recovery: failed payload type, reduction/gene/metadata column when available, and a concise retry/reload hint.
- **D-03:** Preserve the Phase 1 browser payload manifest as the contract source of truth; failure payload additions must update manifest, R producer tests, JS consumer tests, and `DEVELOPMENT.md` together.

### Versioned Cache And Stale Payloads
- **D-04:** Keep versioned browser cache keys mandatory for metadata, reductions, expression, PCA summaries, and cached notification payloads.
- **D-05:** Stale payloads must be ignored when a newer render or transfer request is active; no late-arriving payload may overwrite active scatter state.
- **D-06:** Cache misses should trigger targeted server requests instead of full reloads when the required payload can be regenerated by key, reduction, assay, gene, or metadata column scope.

### Expression Transfer Behavior
- **D-07:** Main scatter expression mode remains first-selected-gene only. Multi-gene displays stay in floating panels and are out of scope for this phase.
- **D-08:** Analysis Mode expression extraction must stay queued/path-based and avoid overlapping large BPCells reads. Do not pass live Seurat/BPCells objects into futures.
- **D-09:** Expression payloads should continue to use Arrow IPC numeric vectors decoded to typed arrays in the browser, not JSON arrays or dense matrix transfers.

### Main Scatter Rendering Reliability
- **D-10:** deck.gl remains the only main scatter rendering path for large datasets; do not introduce canvas/SVG fallbacks for the primary scatter.
- **D-11:** Adaptive rendering thresholds from `AGENTS.md` remain normative: point size, opacity, and pickability must degrade with cell count, including non-pickable behavior above 2M cells.
- **D-12:** Split-panel geometry, labels, legends, titles, and expression/category color behavior should be verified together because regressions commonly appear only after grouping plus splitting plus expression mode combine.

### Lasso And Selection Synchronization
- **D-13:** Lasso selection must work across every scatter panel and keep highlights, selected-cell counts, and total-cell counts synchronized.
- **D-14:** Selection state should survive valid redraws but must clear or reconcile when grouping, split, reduction, or metadata context changes make the old selection ambiguous.

### the agent's Discretion
Planning agents may decide exact test grouping, helper extraction, and whether fixes live in R transfer producers, JS message handlers, scatter lifecycle, or scatter model code. Keep changes minimal and contract-driven: add the smallest implementation needed to satisfy visible reliability and large-data safety without broad UI redesign.

</decisions>

## Existing Code Insights

### Reusable Assets
- `inst/protocol/browser-payload-contracts.json`: use this manifest to drive new or expanded transfer contract tests instead of duplicating message fields in multiple places.
- `tests/testthat/test-browser-payload-contracts.R`: extend for XFER-01 through XFER-04 producer guarantees, basename-only path policy, and IPC column checks.
- `srcjs/index.test.js`: already has Shiny handler mocks and cache tests; extend for visible errors, stale-version ignores, cache misses, readiness, and selection interactions.
- `srcjs/modules/scatter/scatterModel.js`: `validateCellMetaDataPatch()` and `setData()` provide a focused place to test patch length/type validation and partial metadata updates.
- `srcjs/modules/scatter/scatterLifecycle.js`: use lifecycle state tests to prevent late renders, resize blanks, or failed loads from being treated as ready plots.

### Established Patterns
- R-to-JS large payload flow is: R writes Arrow IPC in session temp storage, sends a Shiny custom message with resource basename/version metadata, JS fetches through resource URL helpers, then decodes to typed arrays or compact categorical structures.
- Analysis Mode data access must use Seurat/BPCells helpers as source of truth. Do not create or depend on a mirrored Analysis DuckDB query store.
- Browser payload changes are all-or-nothing: manifest, R producer tests, JS consumer/cache tests, cache-version behavior, and `DEVELOPMENT.md` must move together.
- Main scatter tests should stay deck.gl/model oriented and avoid DOM-heavy or SVG/canvas primary scatter paths.
- Large data paths should prefer typed arrays and categorical encodings, with no repeated full-string arrays for cell-level categorical payloads.

### Integration Points
- Metadata/reduction/PCA/expression producers connect from R helpers into `session$sendCustomMessage()` payloads consumed by `srcjs/index.js`.
- `srcjs/index.js` owns browser cache keys, stale payload filtering, Shiny input feedback, and plot readiness messages.
- `ScatterModel` derives panel data and validates metadata patches before `deckScatter` renders.
- `deckScatter` owns adaptive layer settings, split-panel viewports, lasso bindings, hover labels, and selected-cell visual state.

</code_context>
