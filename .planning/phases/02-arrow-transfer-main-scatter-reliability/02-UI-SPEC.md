# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope

Phase 02 hardens the existing Arrow IPC transfer and main deck.gl scatter UI. It does **not** redesign the app. Preserve the current Shiny/bslib two-sidebar layout, floating plot rail, Bootstrap/Flatly visual language, and deck.gl scatter interaction model while making transfer failures, readiness, stale payloads, adaptive rendering, split panels, legends, labels, and lasso state explicit and recoverable.

Primary user outcome: after loading a large dataset, the user can tell whether metadata, reductions, expression, PCA summaries, and metadata patches are ready, failed, stale, or safely ignored, and can keep using the main scatter without silent blank plots or stale render state.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / Bootstrap light surfaces | Main plot background, floating panels, accordion bodies, status-card interiors |
| Secondary (30%) | Flatly primary `#2C3E50` / `var(--bs-primary)` | Left/right sidebars, rails, overlay badge backgrounds that need white text, active panel framing |
| Accent (10%) | Expression high `#800080` with low `#E5E4E2` | Expression color ramp endpoint, expression legend, selected first-gene visual semantics only |
| Destructive | Flatly danger `#E74C3C` / `var(--bs-danger)` | Destructive actions only; none are introduced by Phase 02 |

Accent reserved for: expression high values, expression legend gradient, and first-selected-gene semantics when a color cue is required. Do **not** use the accent for every button, sidebar control, or category color.

Additional semantic colors:

- Recoverable transfer/render errors use Bootstrap warning styling: background `#FFF3CD`, border `#FFECB5`, text `#664D03`. These errors are warnings because the user can retry, switch reductions/features, or reload the dataset.
- Unrecoverable protocol/schema mismatch may add a danger edge or icon using `var(--bs-danger)`, but the main body still includes clear recovery text.
- Category colors come from the existing D3 hue palette (`hue_pal(n)`) and are data colors, not UI accents.
- Expression colors are a continuous gradient from `#E5E4E2` (zero/low expression) to `#800080` (high expression). Mixed-sign module-score values use the same gradient scaled across the observed range.
- Selected/hovered point outlines use the existing high-contrast layered highlight treatment and must remain visible on both category and expression colors.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Retry transfer |
| Empty state heading | Load a dataset to view the scatter plot |
| Empty state body | Choose a supported dataset. The scatter appears after metadata and one active reduction finish loading. |
| Error state | Could not load {payload}. {short reason}. Try {specific action}, or reload the dataset. |
| Destructive confirmation | None — Phase 02 introduces no destructive actions. |

### Transfer Error Copy Variants

Use these exact copy patterns where payload context is available:

| Payload | Heading | Body / Guidance |
|---------|---------|-----------------|
| Metadata | Metadata could not load | Could not load metadata for this dataset. Retry transfer, or reload the dataset. |
| Metadata patch | Metadata update could not apply | The update for `{columns}` could not be applied. Existing metadata is still shown. Retry the action or reload the dataset. |
| Reduction | Reduction could not load | Could not load `{reduction}`. Try switching reductions, retry transfer, or reload the dataset. |
| Batched reductions | Scatter could not initialize | No active reduction finished rendering. Retry transfer, or reload the dataset. |
| Expression | Expression could not load | Could not load expression for `{gene}` in `{assay}`. The category scatter remains available. Retry transfer or choose another gene. |
| PCA summary | PCA summary unavailable | PCA standard deviations could not load. The main scatter is still usable. Reopen ElbowPlot after retrying the transfer. |
| Render setup | Scatter render failed | The previous scatter view was restored. Retry transfer, switch settings, or reload the dataset. |
| Stale payload ignored | Do not show user-facing copy | Late payloads are implementation details. Ignore them silently unless the active request later fails. |

Copy rules:

- Always name the failed payload type. Include reduction, gene, assay, or patch columns when available.
- Never expose local filesystem paths, temp file paths, server stack traces, or raw exception internals in user-facing copy.
- Use one primary recovery instruction first: retry transfer, switch reductions, choose another gene, or reload dataset.
- Use `reload the dataset`, not `refresh the page`, unless the server session is unrecoverable.

## Visible Transfer And Render Error Contract

### Placement

- Metadata, reduction, expression, metadata patch, and scatter render setup failures display inside the main plot container `#mainClusterPlot-clusterPlot`.
- Default placement is top-left, 16px from the plot container edge, above deck.gl layers and below any full-screen app chrome: `position: absolute; top: 16px; left: 16px; z-index >= 10; max-width: min(34rem, calc(100% - 32px))`.
- The error must not cover the persistent `Total | Selected` count badge in the top-right.
- If a valid previous scatter exists, keep it visible behind the error overlay. If no valid scatter exists, show the error over the empty plot area instead of leaving a blank canvas.
- PCA-only failures are shown in the ElbowPlot floating panel status area when that panel is open; they do not block the main scatter.

### Visual Treatment

- Use warning colors for recoverable transfer/render errors: `#FFF3CD` background, `#FFECB5` border, `#664D03` text, 8px radius, 12px vertical by 16px horizontal padding.
- Include a semibold heading line and one guidance line. Keep the overlay to two visible lines when possible.
- If a retry action is implemented as a button/link, it uses Bootstrap primary styling, 44px minimum target height, visible focus ring, and label `Retry transfer`.
- Error overlay must be dismissible only by a successful current payload/render, an explicit retry success, or dataset reload. Do not auto-hide on timers.

### Severity And Recovery

- Fetch/decode/write failure: warning severity; hide any initial loading waiter; show payload-specific recovery guidance.
- Stale payload ignored: no user-facing error; keep current plot and current loading state for the active request.
- Protocol/schema mismatch: warning with optional danger icon; tell the user to reload the dataset. Developers see details in console/tests, not in user copy.
- Render replacement failure: restore previous plot DOM/instance atomically and show `Scatter render failed` copy.

### Accessibility

- Error overlay uses `role="alert"` and `aria-live="assertive"`.
- Retry controls are reachable by keyboard and announce as buttons/links with descriptive names.
- Error text must not rely on warning color alone; the heading includes the word `could not` or `failed`.

## Readiness, Loading, And Stale Payload Contract

### Global Rules

- Initial plot readiness is reported only after metadata is loaded and exactly one real active reduction has rendered.
- A waiter/spinner may be visible during initial load but must settle on success **or** visible failure. Never leave users behind an indefinite loading overlay.
- Versioned cache keys are mandatory for metadata, reductions, expression, PCA summaries, and metadata patch notifications.
- Late-arriving stale payloads must never overwrite active scatter state. Ignore stale payloads silently and retain the current plot.
- Cache misses trigger targeted server requests whenever possible; do not force full dataset reload when a reduction/gene/column-scoped payload can be regenerated.

### Payload-Specific States

| Payload | Loading State | Ready State | Failure State | Stale State |
|---------|---------------|-------------|---------------|-------------|
| Metadata | Initial waiter or plot-local spinner while `meta_ready` is active | Category/sidebar choices and metadata-backed plot state update; clear plot transfer error | Show `Metadata could not load`; settle initial waiter | Ignore if `metaVersion` is older than active dataset/request |
| Full reduction | Keep current scatter if available; otherwise show initial waiter | Render requested active reduction before reporting readiness | Show `Reduction could not load`; keep previous scatter if available | Ignore if `reductionVersion` or active reduction request is stale |
| Batched reductions | Resolve server `activeReduction` first, then deterministic fallback to first payload entry | Render one active reduction, then warm inactive reduction cache | Show `Scatter could not initialize` if no active reduction renders | Ignore stale batch; do not use stale DOM select value |
| Expression | Keep category scatter interactive; show expression loading/status for first selected gene | Expression panel/legend reflects first selected gene only | Show `Expression could not load`; category scatter remains available | Ignore if `exprVersion`, assay, or gene is no longer active |
| PCA summary | If ElbowPlot is open, show `PCA summary loading…` in panel status | ElbowPlot status clears and client-side plot can render | Show `PCA summary unavailable` in ElbowPlot status | Ignore if `reductionVersion` is stale |
| Metadata patch | Current scatter remains visible while patch applies | Merge patch into existing metadata; refresh only if active plot columns are touched | Show `Metadata update could not apply`; retain previous metadata | Ignore patch if version is stale or patch length/type mismatches active metadata |

### Stale UI Behavior

- Do not flash stale warnings for normal races. Stale payload handling is a reliability behavior, not a user-facing event.
- If the active request is still loading while stale payloads arrive, keep the active loading state.
- If the active request later fails, show the active failure copy; do not mention the ignored stale payload.

## Main Scatter Visual Contract

### Renderer And Performance

- Main scatter uses deck.gl `ScatterplotLayer` only. No canvas/SVG primary scatter fallback is allowed.
- Large numeric payloads are decoded to TypedArrays. Categorical metadata stays compact with index arrays plus level lookup.
- Resize handling remains debounced; do not add DOM work inside point render loops.

### Adaptive Point Settings

Use the AGENTS.md thresholds exactly:

| Cell Count | Point Size | Opacity | Pickable |
|------------|------------|---------|----------|
| < 15,000 | 4 | 0.8 | true |
| 15K–50K | 3 | 0.7 | true |
| 50K–500K | 2 | 0.6 | true |
| 500K–1M | 1 | 0.5 | true |
| 1M–2M | 0.5 | 0.4 | true |
| > 2M | 0.2 | 0.2 | false |

Above 2M cells, hover/picking is disabled for performance. Explicit lasso selection still uses the lasso contract below and must update counts when completed.

### Plot Modes, Titles, And Panels

| Mode | Panels | Titles | Color Semantics |
|------|--------|--------|-----------------|
| Category only, no split | 1 | `{group_by}` | Category palette by group |
| Category + expression, no split | 2 | `{group_by}` and `{gene}` | Left/category panel uses group palette; right/expression panel uses expression gradient |
| Category + expression, exactly two split levels | 4 | `{split level} : {group_by}` and `{split level} : {gene}` pairs | Category and expression panels repeat per split level |
| Category with multi-split | `nSplit` | `{split level}` | Each panel colored by category group |
| Expression with multi-split (>2 split levels) | `nSplit` | `{split level}` | Each panel colored by first selected gene expression |

Panel title rules:

- Place panel titles top-center within each panel, 16px / 600, black text, above the plot points.
- Long metadata names or split labels must truncate with a tooltip/title attribute rather than overflowing into neighboring panels.
- Null, empty, or missing split/category values are not rendered as visible `undefined` levels.

### Split-Panel Geometry

Use the existing adaptive grid rules:

| Number of Panels | Minimum Panel Size |
|------------------|--------------------|
| 1–11 | 400px |
| 12–23 | 320px |
| 24–47 | 280px |
| 48–71 | 240px |
| 72–95 | 200px |
| 96+ | 180px |

- A single row with one or two panels may fill available height.
- Multi-row layouts use square panels and allow plot-container scrolling rather than shrinking below the minimum panel size.
- Grid gaps use 8px unless existing code already supplies a smaller internal panel gap.

### Legends And Labels

- Category legends list only non-null category levels. Each entry includes a color block, label, and point count.
- Legend labels use ellipsis truncation and a title tooltip for full text.
- Legend counts use thousands separators via `Intl.NumberFormat`.
- Expression legend shows the first selected gene name or `ModuleScore` and the low-to-high gradient from `#E5E4E2` to `#800080`.
- Category labels draw at category centroids only on category-colored panels. Expression panels do not draw category labels.
- Label size slider range remains 0–50 with default 14. A value of 0 hides labels.

### First-Selected-Gene Contract

- Main scatter expression mode uses only `selectedFeatures[0]`.
- When multiple genes are selected, the first selected gene is visually emphasized in the sparkline list and is the only gene reflected in the main scatter title, expression legend, and expression colors.
- Multi-gene expression displays remain in floating panels and are out of scope for Phase 02.

## Lasso And Selection Contract

### Interaction

- Lasso gesture remains `SHIFT` + drag on the scatter canvas.
- Lasso polygon uses black stroke at 80% opacity and yellow fill at 15% opacity.
- Lasso hit-testing must work in every panel, including non-origin panels and high-cardinality split layouts.
- Selecting cells in one panel highlights the same cell IDs in every other panel where those cells appear.

### Counts And Highlights

- The persistent top-right badge always displays `Total` and `Selected` counts.
- Badge copy is exactly `Total {n}` and `Selected {n}` with thousands separators.
- The badge uses a dark high-contrast background (`var(--bs-primary)` / `#2C3E50` at >= 0.9 opacity) with white text.
- Selected cells use the existing three-layer highlight treatment: outer same-color ring, dark inner contrast ring, and body color. Highlight must remain visible on expression and category colors.
- Hover crosshair remains panel-local and does not change selection count.

### Persistence And Clearing

- Selection persists across valid redraws when dataset version and cell IDs remain the same: resize, label-size changes, expression payload arrival, cache rehydrate, and category/expression panel pairing.
- Selection reconciles by cell ID when group/split settings change. If selected cell IDs are still visible, keep them highlighted across applicable panels; if no selected IDs remain visible or context is ambiguous, clear selection.
- Selection clears on new dataset load, incompatible metadata/reduction version changes, manual deselect, assign completion, or explicit empty lasso clear.
- Clearing selection immediately updates the top-right badge to `Selected 0` and sends the cleared selection state to Shiny.

## Accessibility And Responsiveness Contract

### Accessibility

- New or modified non-canvas controls must be semantic `button`, `select`, `input`, or `a` elements with accessible names.
- Error overlays use `role="alert"` and `aria-live="assertive"`; readiness/status updates use `aria-live="polite"`.
- Do not rely on color alone: errors include explicit text, legends include labels/counts, and selected count is visible text.
- Keyboard focus indicators must be visible for retry buttons, sidebar controls, rails, floating panel close/action buttons, and the info widget.
- New interactive targets must meet 44px minimum touch target size. Existing smaller rail buttons may remain unless touched.
- Canvas-only lasso remains mouse/pointer-driven, but equivalent category-based selection and selected-count feedback must remain available through existing sidebar controls.
- Tooltip/hover content is supplemental only; no required recovery instruction may exist only in a hover tooltip.

### Responsiveness

- The app remains optimized for desktop analysis screens. Do not redesign for mobile in Phase 02.
- At 200% zoom, sidebars must scroll vertically, plot error overlays must wrap within the plot container, and the count badge must remain visible.
- Split-panel layouts scroll inside the plot surface when needed; do not shrink panels below the adaptive minimums.
- Floating panels retain existing viewport clamps: width/height must not exceed `calc(100vw - 1rem)` or `calc(100vh - 1rem)`.
- Error overlays and count badges must not block lasso interaction outside their own bounds.

## Explicit Non-Goals

- No canvas or SVG primary scatter fallback for million-cell workflows.
- No broad design-system overhaul, no shadcn/Tailwind introduction, and no React component migration.
- No multi-gene composite coloring in the main scatter. The main scatter uses the first selected gene only.
- No new floating analysis panel behavior beyond status/error consistency needed for PCA summary readiness.
- No new portable artifact formats, Analysis Mode mutation workflows, or assistant UI.
- No full metadata, reduction, or expression JSON payloads.
- No user-facing exposure of temp paths, local server paths, raw stack traces, credentials, or raw matrices.
