## Implementation Decisions

### Transfer Failure Visibility
- **D-01:** Treat fetch, decode, and IPC write failures as visible plot-state failures, not silent console-only errors or stuck waiters.
- **D-02:** Prefer in-plot or plot-adjacent error state that leaves enough context for recovery: failed payload type, reduction/gene/metadata column when available, and a concise retry/reload hint.
- **D-03:** Preserve the Phase 1 browser payload manifest as the contract source of truth; failure payload additions must update manifest, R producer tests, JS consumer tests, and `DEVELOPMENT.md` together.

### Versioned Cache And Stale Payloads
- **D-04:** Keep versioned browser cache keys mandatory for metadata, reductions, expression, PCA summaries, and cached notification payloads.
- **D-05:** Stale payloads must be ignored when a newer render or transfer request is active; no late-arriving payload may overwrite active scatter state.
- **D-06:** Cache misses should trigger targeted server requests instead of full reloads when the required payload can be regenerated by key, reduction, assay, gene, or metadata column scope.

### Expression Transfer Behavior
- **D-07:** Main scatter expression mode remains first-selected-gene only. Multi-gene displays stay in floating panels and are out of scope for this phase.
- **D-08:** Analysis Mode expression extraction must stay queued/path-based and avoid overlapping large BPCells reads. Do not pass live Seurat/BPCells objects into futures.
- **D-09:** Expression payloads should continue to use Arrow IPC numeric vectors decoded to typed arrays in the browser, not JSON arrays or dense matrix transfers.

### Main Scatter Rendering Reliability
- **D-10:** deck.gl remains the only main scatter rendering path for large datasets; do not introduce canvas/SVG fallbacks for the primary scatter.
- **D-11:** Adaptive rendering thresholds from `AGENTS.md` remain normative: point size, opacity, and pickability must degrade with cell count, including non-pickable behavior above 2M cells.
- **D-12:** Split-panel geometry, labels, legends, titles, and expression/category color behavior should be verified together because regressions commonly appear only after grouping plus splitting plus expression mode combine.

### Lasso And Selection Synchronization
- **D-13:** Lasso selection must work across every scatter panel and keep highlights, selected-cell counts, and total-cell counts synchronized.
- **D-14:** Selection state should survive valid redraws but must clear or reconcile when grouping, split, reduction, or metadata context changes make the old selection ambiguous.

### the agent's Discretion
Planning agents may decide exact test grouping, helper extraction, and whether fixes live in R transfer producers, JS message handlers, scatter lifecycle, or scatter model code. Keep changes minimal and contract-driven: add the smallest implementation needed to satisfy visible reliability and large-data safety without broad UI redesign.

### Deferred Ideas (OUT OF SCOPE)
None — discussion stayed within Phase 2 scope.

## Summary

Phase 02 should be planned as a hardening phase around existing runtime seams, not as a rewrite. Phase 01 already verified the Analysis Mode backend helpers, the browser payload manifest, producer/consumer tests, and documentation guard; Phase 02 should extend those contracts to cover visible failure states, active-reduction readiness, stale payload ignores, metadata patch behavior, and main scatter interaction regressions. [VERIFIED: .planning/phases/01-runtime-contract-backbone/01-VERIFICATION.md]

The most important implementation axis is the R-to-JS Arrow IPC path: R producers write basename-addressed IPC files under session resource directories, Shiny sends versioned messages, JavaScript fetches and decodes Arrow buffers, then the scatter model and deck.gl renderer consume TypedArrays or compact categorical maps. [VERIFIED: R/fct_backend_transfer_adapter.R; VERIFIED: srcjs/index.js; VERIFIED: srcjs/modules/arrowReader.js] Official Arrow docs confirm `write_ipc_stream()` writes Arrow IPC streams and Arrow JS `tableFromIPC()` deserializes IPC to a Table. [CITED: https://arrow.apache.org/docs/r/reference/write_ipc_stream.html] [CITED: https://arrow.apache.org/js/current/functions/Arrow.dom.tableFromIPC.html]

The second implementation axis is main scatter state safety: deck.gl should remain the only renderer, the plot should use binary attributes for positions/colors, failed replacement renders should preserve the previous view, and lasso/selection/count state should be reconciled by cell ID across valid redraws. [VERIFIED: srcjs/modules/deckScatter.js; VERIFIED: srcjs/modules/lasso.js] deck.gl docs specifically warn that data-prop changes and accessor CPU work are expensive for large layers, recommend binary data/attributes for performance-sensitive apps, and note picking has off-screen rendering overhead. [CITED: https://deck.gl/docs/developer-guide/performance]

**Primary recommendation:** Plan small, contract-first waves that extend existing R producer tests, JS consumer/cache tests, and scatter model/deck tests before touching broad UI or data-path code. [VERIFIED: 02-CONTEXT.md]

## Implementation Approach

1. **Start with contracts and tests:** Extend manifest-driven R tests for failure payload shape, basename-only path policy, metadata patch column scope, IPC columns, and no forbidden local path fields before implementation changes. [VERIFIED: inst/protocol/browser-payload-contracts.json; VERIFIED: tests/testthat/test-browser-payload-contracts.R]
2. **Harden JS transfer handlers:** Add payload-specific error handling for `meta_ready`, `meta_patch_ready`, `reduction_ready`, `reductions_ready`, `reduction_cached`, `pca_ready`, `expr_ready`, and `expr_cached`, with stale request checks before state writes and with waiters settled on failure. [VERIFIED: srcjs/index.js; VERIFIED: 02-UI-SPEC.md]
3. **Preserve current scatter on failure:** Use the existing atomic replacement behavior as the model: never destroy the previous deck instance until the replacement succeeds, and show a recoverable overlay if render setup fails. [VERIFIED: DEVELOPMENT.md; VERIFIED: srcjs/index.js]
4. **Keep expression extraction queued and single-feature for the main scatter:** Use the existing `expression_queue`, cache keys, and `extract_bpcells_expr_to_ipc()` chunk writer; add tests around duplicate queued keys, failures, stale versions, and first-selected-gene UI state. [VERIFIED: R/mod_InputFeature.R; VERIFIED: R/fct_bpcells_backend.R]
5. **Treat scatter reliability as model+renderer state, not DOM redesign:** Add focused tests for `ScatterModel`, `scatterLayout`, `lasso`, and deck layer option generation; avoid introducing React/Tailwind/canvas/SVG or broad styling changes. [VERIFIED: 02-UI-SPEC.md; VERIFIED: srcjs/modules/scatter/scatterModel.test.js]

### System Architecture Diagram

```mermaid
flowchart TD
  A[Dataset loaded in Analysis or Explore mode] --> B{Payload request type}
  B -->|metadata or patch| C[R metadata helper / Explore query plan]
  B -->|reduction or PCA| D[R reduction/PCA helper / Explore query plan]
  B -->|single gene expression| E[Queued BPCells matrix_dir or Explore expression query]
  C --> F[Arrow IPC writer in session temp resource dir]
  D --> F
  E --> G[Chunked Arrow IPC RecordBatchStreamWriter]
  F --> H[Shiny sendCustomMessage with basename + version]
  G --> H
  H --> I[JS handler in srcjs/index.js]
  I --> J{Version/cache check}
  J -->|stale| K[Ignore without user-facing warning]
  J -->|cache miss| L[Set targeted Shiny cacheMiss input]
  J -->|current| M[Fetch /data/meta|reduction|expr basename]
  M --> N{Fetch/decode/schema success?}
  N -->|no| O[In-plot or panel error; settle waiter; preserve previous plot]
  N -->|yes| P[Arrow decode to TypedArrays / categorical index maps]
  P --> Q[ScatterModel merge/derive panel data]
  Q --> R[deck.gl ScatterplotLayer binary attributes]

```

**What:** R writes an IPC file to a session resource directory and sends only a basename plus version fields to JS. [VERIFIED: R/fct_backend_transfer_adapter.R; VERIFIED: inst/protocol/browser-payload-contracts.json]

### Pattern 2: Chunked BPCells expression IPC writer

**What:** Open the BPCells matrix by directory path, stream one feature vector into Arrow record batches, and close writer/sink reliably. [VERIFIED: R/fct_bpcells_backend.R]

**When to use:** Use for Analysis Mode expression payloads for the main scatter and selected-gene sparkline state. [VERIFIED: R/mod_InputFeature.R]

### Pattern 4: deck.gl binary attributes for scatter points

**What:** Build `Float32Array` positions and `Uint8Array` colors, then pass them as `data.attributes` to `ScatterplotLayer`. [VERIFIED: srcjs/modules/deckScatter.js]

**When to use:** Use for every main scatter panel; avoid object arrays and accessor-heavy per-point work. **Example:**

### Anti-Patterns to Avoid

- **Console-only async failures:** Users must see recoverable plot-state errors when transfer fetch/decode/write/render fails. [VERIFIED: 02-CONTEXT.md; VERIFIED: 02-UI-SPEC.md]
- **Late payload state writes:** A stale payload must not overwrite current metadata, reduction, expression, PCA, or patch state. [VERIFIED: 02-CONTEXT.md]
- **Live object futures for expression:** Do not pass Seurat/BPCells objects into futures for large expression extraction; use path/query-plan work. [VERIFIED: AGENTS.md; VERIFIED: R/mod_InputFeature.R]
- **Full JSON tables:** Do not transfer full metadata, reduction, or expression data as JSON arrays. [VERIFIED: .planning/REQUIREMENTS.md; VERIFIED: AGENTS.md]
- **Deck layer object-array rebuilds for every interaction:** Do not replace binary buffers with per-point object arrays or expensive accessors. [CITED: https://deck.gl/docs/developer-guide/performance]

## Common Pitfalls

### Pitfall 1: Stale payload overwrites current scatter state
**What goes wrong:** A late reduction/expression/metadata response writes to `reglElementData` after a newer dataset or request is active. [VERIFIED: 02-CONTEXT.md]
**Why it happens:** Version checks can occur before fetch but not again after asynchronous fetch/decode finishes. [VERIFIED: srcjs/index.js]
**How to avoid:** Gate both before and immediately before state mutation using active version/request identity. [VERIFIED: inst/protocol/browser-payload-contracts.json]
**Warning signs:** Tests pass for synchronous stale messages but fail when stale fetch promises resolve after a newer payload. [VERIFIED: srcjs/index.test.js]

### Pitfall 2: Visible error overlay lacks payload context
**What goes wrong:** Users see generic failure copy or only console errors for metadata patch, expression, PCA, or render setup failures. [VERIFIED: srcjs/index.js; VERIFIED: 02-UI-SPEC.md]
**Why it happens:** Current error handling is strongest for metadata/reduction paths and weaker for `meta_patch_ready`, `pca_ready`, `expr_ready`, and `expr_cached`. [VERIFIED: srcjs/index.js]
**How to avoid:** Normalize errors into payload-specific headings/body copy from the UI spec and keep raw paths/stack traces out of user copy. [VERIFIED: 02-UI-SPEC.md]
**Warning signs:** `console.error("There was a problem:", error)` without `handlePlotTransferError()` or panel status update. [VERIFIED: srcjs/index.js]

### Pitfall 3: Expression jobs overlap and spike memory
**What goes wrong:** Multiple large BPCells reads or dense vector materializations happen concurrently. [VERIFIED: AGENTS.md]
**Why it happens:** Feature selection can enqueue several genes and cached/missing paths can trigger repeated requests. [VERIFIED: R/mod_InputFeature.R]
**How to avoid:** Preserve one active expression job per session, duplicate-key suppression, chunked IPC writing, and first-selected-gene main scatter behavior. [VERIFIED: R/mod_InputFeature.R; VERIFIED: R/fct_bpcells_backend.R; VERIFIED: DEVELOPMENT.md]
**Warning signs:** Futures receive `seuratObj`, `object`, or raw matrix fields, or expression writer returns full dense matrices before IPC writing. [VERIFIED: tests/testthat/test-analysis-backend-contract.R]

### Pitfall 4: Multi-panel lasso assumes first-panel coordinates
**What goes wrong:** Lasso only selects correctly in panel 0 or misses high-cardinality split panels. [VERIFIED: DEVELOPMENT.md]
**Why it happens:** Canvas-global and panel-local coordinates can be confused after viewports are offset or panned. [VERIFIED: srcjs/modules/lasso.js; VERIFIED: srcjs/modules/scatter/scatterCoordinates.test.js]
**How to avoid:** Test `projectWorldToCanvas()`/viewport selection for non-origin panels and keep `panelViewId` on layers. [VERIFIED: srcjs/modules/lasso.js; VERIFIED: srcjs/modules/deckScatter.js]
**Warning signs:** Selected count changes but highlights appear only in one panel or repeated cluster/expression panel pairs do not mirror. [VERIFIED: srcjs/modules/deckScatter.js]

### Pitfall 5: Adaptive picking is accidentally re-enabled at >2M cells
**What goes wrong:** Hover/picking remains enabled for extreme point counts and causes GPU/CPU responsiveness problems. [VERIFIED: AGENTS.md]
**Why it happens:** `shouldEnablePicking()` can re-enable picking when zoomed in; this may conflict with the UI spec's strict >2M non-pickable behavior if not tested. [VERIFIED: srcjs/modules/deckScatter.js; VERIFIED: 02-UI-SPEC.md]
**How to avoid:** Planner should decide whether to preserve zoomed-in re-enable behavior or align strictly to UI spec; add tests either way. [VERIFIED: srcjs/modules/deckScatter.js; VERIFIED: 02-UI-SPEC.md]
**Warning signs:** A >2M fixture creates pickable base layers at initial zoom. [VERIFIED: srcjs/modules/deckScatter.js]

### Pitfall 6: Metadata patch refreshes too much or too little
**What goes wrong:** Column-scoped patches either force full metadata reloads or fail to refresh plots that depend on changed group/split columns. [VERIFIED: R/fct_backend_transfer_adapter.R; VERIFIED: srcjs/index.js]
**Why it happens:** Patch column scope and active plot dependencies are separate concepts. [VERIFIED: srcjs/index.js]
**How to avoid:** Keep producer payloads column-scoped and let JS refresh only when changed columns affect active `group_by`, `split_by`, VlnPlot, DotPlot, or sidebar state. [VERIFIED: srcjs/index.js]
**Warning signs:** Patch IPC contains unrelated metadata columns or `metaPatchProcessed.refreshMainPlot` is wrong. [VERIFIED: tests/testthat/test-browser-payload-contracts.R; VERIFIED: srcjs/index.test.js]
