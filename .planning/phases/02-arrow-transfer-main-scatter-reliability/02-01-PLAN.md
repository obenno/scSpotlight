## Phase Goal

**As a** single-cell analyst, **I want to** load large datasets and interact with a reliable Arrow-backed deck.gl scatter, **so that** I can inspect metadata, reductions, expression, and selections without silent failures or stale render state.

<objective>
Deliver the first Phase 02 vertical slice: metadata and active-reduction transfer reliability for XFER-01, XFER-02, and SCAT-05, with visible plot-state failures, versioned stale-payload gates, and readiness only after one current active reduction has rendered.

Purpose: A loaded dataset must either render a current scatter or show a recoverable in-plot transfer failure; users must not be left with a blank deck surface, stale reduction, raw path disclosure, or indefinite waiter.
Output: Manifest-backed transfer failure payloads, R producer failure notifications, JS visible error and stale-state handling, targeted tests, rebuilt browser bundle, and DEVELOPMENT documentation.
</objective>

## Artifacts this phase produces

| Artifact | Type | Contract |
|---|---|---|
| `transfer_error` | browser message contract | Sanitized failure notification for metadata, reduction, batched reduction, PCA, expression, and metadata patch write failures; Plan 01 implements metadata/reduction/PCA uses and later plans reuse it. |
| `make_transfer_error_payload()` | R helper | Creates basename-safe, path-free, stack-free failure payloads with `payloadType`, `reasonCode`, `version`, and scoped context fields. |
| `showPlotTransferError()` / related formatter | JS UI behavior | Renders warning-colored top-left plot overlay with `role="alert"`, `aria-live="assertive"`, payload-specific heading/body, and no raw paths. |
| Active-reduction stale gate | JS state rule | Checks `reductionVersion` and active request identity before fetch and again before plot state mutation. |
| Metadata stale gate | JS state rule | Ignores stale `meta_ready` or metadata `transfer_error` versions when a newer dataset/request is active. |
| Phase 02 docs guard text | documentation contract | `DEVELOPMENT.md` documents visible transfer failures and stale payload policy, guarded by `test-development-contract-docs.R`. |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| R producer failures → browser message | R exceptions cross into sanitized browser-visible failure payloads. |
| Session resource fetch → Arrow decoder | Browser fetches basename-scoped Arrow IPC resources and decodes untrusted binary payloads for plot state. |
| Browser transfer state → deck.gl scatter | Decoded metadata/reduction data mutates the current scatter model and readiness state. |
| Error overlay → user | User-facing copy renders scoped payload context without raw paths or stack traces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `transfer_error` browser payload | mitigate | `make_transfer_error_payload()` plus manifest tests reject local paths, stack traces, raw condition text, `filePath`, `output_file`, and `matrix_dir`. |
| T-02-02 | Tampering | metadata/reduction stale payloads | mitigate | `srcjs/index.js` checks active version/request identity before fetch and immediately before state mutation. |
| T-02-03 | Denial of Service | stuck initial waiter | mitigate | `handlePlotTransferError()` settles only the active initial request and hides the spinner on current failures. |
| T-02-04 | Information Disclosure | user-facing plot error text | mitigate | Overlay uses payload-specific UI-spec copy via `textContent` and never renders raw exception internals. |
| T-02-05 | Tampering | protocol contract drift | mitigate | Manifest, R producer tests, JS handler tests, cache behavior, and `DEVELOPMENT.md` are updated in this same plan per D-03. |
| T-02-SC | Tampering | Package installs | accept | This plan installs no npm, pip, cargo, R, or system packages. |
</threat_model>
