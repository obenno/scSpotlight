<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Uploaded/local Analysis input → Seurat/BPCells object | User-selected files become in-memory and on-disk assay state. |
| Seurat processing helpers → app state | Processing/PCA helpers mutate object layers, reductions, graphs, and metadata before transfer indicators run. |
| R load/process errors → user notifications | Load/process failures can cross into visible UI copy. |
| App state → Phase 02 transfer producers | Processed metadata/reductions/expression later flow through existing Arrow IPC contracts. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | `run_memory_conserving_pca()` / `run_memory_conserving_processing()` | mitigate | Add tests and helper enforcement so final Analysis app state has no dense `scale.data` after processing/PCA. |
| T-03-02 | Tampering | Analysis input type routing in `R/mod_dataInput.R` | mitigate | Fixture tests plus source guards keep Explore parquet bundles out of Analysis Mode and preserve supported `.Rds`, `.h5ad`, BPCells bundle, and 10x-style branches. |
| T-03-03 | Denial of Service | BPCells backing conversion | mitigate | Tests assert BPCells-backed layers where available and block unsupported matrix coercion from failing late with less actionable errors. |
| T-03-04 | Information Disclosure | load/process error notifications | mitigate | Plans require user-visible load failures to avoid raw absolute paths, temp paths, stack traces, and credential-like values; raw diagnostics stay server-side. |
